# IDRX payout: status

Date: 22 Nov 2026. State: code-ready and dry-run verified against live mainnet state. No live payout has ever been sent; the IDRX transfer to a genuine freelancer is still unproven live and waits for the first genuine order.

## Why this is a package, not a desk server route

The desk server's job ends at order settlement (Self gate, x402 payment, handler). Paying out is an operator step run from the treasury after delivery is accepted, under Duan's notify-first rule: the exact transaction is announced to him and approved before anything is sent. A library plus CLI (src/payout.ts), mirroring packages/identity (ERC-8004 registration, the other operator-invoked chain write), matches that operating model. An HTTP route that moves money would not.

## Done

- Payout module in src/index.ts: executePayout(recipient, amountIDRX) from the treasury wallet only (any other account is refused), all amounts through @tanda/money (IDRX 2 decimals, precision guard rejects more), transfer calldata built exactly, tagged bytes assembled with the ERC-8021 suffix from @tanda/wallet.
- Dry run by default, the identity pattern: pre-flight, simulation of the exact tagged bytes, full would-be summary returned, nothing broadcast. Live sends need dryRun: false AND the execution opt-in, the textile pattern: PAYOUT_EXECUTION_ENABLED=true/1 or the executionEnabled option. With the flag off, a live request throws before any chain read; a test proves it cannot broadcast. With the flag on: pre-flight, simulate, broadcast through the tagged wallet client, await receipt, verifyTx tag check (an untagged payout throws).
- Pre-flight checks in the payout path (runPayoutPreflight), all reported, no short circuit: amount positive; recipient is not the agent wallet; recipient is not the treasury; treasury IDRX balance covers the amount; and the no prior inbound check, which operationalizes the recruitment rule that our payout must be the first funds we ever send the freelancer wallet: the recipient's IDRX and CELO balances are read, and the recipient's inbound IDRX and USDT Transfer history is scanned for any transfer from the agent or treasury wallet. Any hit refuses the payout with the offending transaction named. The scan walks eth_getLogs in 5,000 block chunks (the public forno RPC maximum range); a floor block may be passed when one is provably safe (for example block 83413939, where the agent wallet was first funded: neither Tanda wallet has any onchain existence before it). The evidence pack's third-party step independently re-checks the full inbound history on CeloScan.
- Evidence pack writer in src/evidence.ts: emits a completed EVIDENCE-PACK.md instance per order into orders/<orderId>/ (project folder), following the template section by section, CeloScan links for every hash, the 5-step verification guide filled in. Fields the caller does not supply render as TODO placeholders, never blanks and never invented values; a sample flag adds a banner stating the pack is not a freelancer order.
- CLI scripts: src/payout.ts (dry run default, --live plus flag for a real send, --from-block for the scan floor) and src/sample-pack.ts (generates the SAMPLE pack).
- Tests: 23 in this package (flag behavior, calldata encoding, tagged bytes, every pre-flight refusal, dry run broadcasts nothing, flag-off live cannot broadcast, flag-on live broadcasts once through the tagged client, non-treasury account refused, evidence writer sections, links, TODO behavior, sample banner, per-order folder write).
